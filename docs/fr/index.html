Le tableau d'interrupteurs

La config SSH est le setup

Voxtunnel lit ~/.ssh/config et donne un interrupteur à chaque host qui a une clé. Rien à déclarer, rien à dupliquer.

Un interrupteur maître Transmission

Un clic coupe tous les streams sans perdre la sélection par host. Rétabli, les streams dont l'interrupteur est ON reviennent.

Vit dans la barre système

La fenêtre est optionnelle : l'icône du tray porte les mêmes interrupteurs dans son menu. Icône verte quand la transmission est active, rouge barrée quand la ligne est coupée.

Le serveur entend un vrai micro

L'audio atterrit dans la carte loopback snd-aloop. Transcription vocale, assistants ou saisie vocale de Claude Code l'enregistrent comme du matériel local.

Des voyants honnêtes, pas de retry magique

Un petit écran par host indique si le bout distant est prêt. Un stream mort repasse son interrupteur à OFF et dit pourquoi. La latence est un slider, pas un mystère.

L'invocation

serveur (VPS)
# depuis github.com/remmmi/voxtunnel/releases/latest
sudo apt install ./voxtunnel-server_*.deb
# charge snd-aloop maintenant et à chaque démarrage - purement additif
client (bureau Linux)
# même page de releases, le fichier voxtunnel_*.deb
sudo apt install ./voxtunnel_*.deb
voxtunnel
depuis les sources (sans root)
git clone https://github.com/remmmi/voxtunnel.git
cd voxtunnel/client
./install.sh          # lanceur de menu ; --autostart pour le démarrage de session
python3 voxtunnel-tray.py
# côté serveur depuis le même clone, en root sur le VPS :
#   sudo ../server/setup-vps.sh --persist
Windows — WSL2, recommandé
# le client Linux tourne tel quel dans WSL2 : WSLg relaie le micro
# Windows et affiche la fenêtre sur le bureau Windows
wsl --install -d Debian
# puis, dans WSL, avec le même voxtunnel_*.deb que ci-dessus :
sudo apt install ./voxtunnel_*.deb
voxtunnel
# les clés SSH vont dans le home WSL (~/.ssh), pas celui de Windows
# pas de WSL ? voie native (expérimentale, pas encore de build) : client-windows/
macOS — depuis les sources, expérimental
# pas encore de build packagé : l'app de barre de menus se lance depuis un clone
brew install ffmpeg python
pip3 install PyQt5
git clone https://github.com/remmmi/voxtunnel.git
python3 voxtunnel/client/voxtunnel-tray.py
# macOS demande la permission micro à la première capture - détails dans client-macos/

Vous avez un Mac ou une machine Windows ? Ces clients n'ont jamais vu que des runners CI. Si vous avez dix minutes pour en essayer un sur du vrai matériel, ouvrez une issue avec ce qui a marché et ce qui a cassé — même « ça se lance » vaut de l'or.

sans interface graphique
# Linux / WSL - le moteur est livré avec le .deb :
VPS_HOST=user@mon-vps /usr/share/voxtunnel/voxtunnel.sh --check
VPS_HOST=user@mon-vps /usr/share/voxtunnel/voxtunnel.sh
# macOS : client-macos/voxtunnel.sh - Windows : client-windows\voxtunnel.cmd user@vps "Nom du micro"
