The control room

Voxtunnel

The switchboard

The SSH config is the setup

Voxtunnel reads ~/.ssh/config and gives every host with a key its own switch. Nothing to declare, nothing to duplicate.

One master Transmission toggle

One click cuts every stream without losing the per-host selection. Flipped back, the streams whose switch is ON return.

Lives in the system tray

The window is optional: the tray icon carries the same switches in its menu. Green icon while transmission is on, red crossed icon when the line is cut.

The server hears a real microphone

Audio lands in the snd-aloop loopback card. Speech-to-text, voice assistants or Claude Code voice input record it like local hardware.

Honest lights, no magic retry

A monitor glyph per host shows if the far end is ready. A dead stream flips its own switch off and says why. Latency is a slider, not a mystery.

The summoning

server (VPS)
# from github.com/remmmi/voxtunnel/releases/latest
sudo apt install ./voxtunnel-server_*.deb
# loads snd-aloop now and at every boot - purely additive
client (Linux desktop)
# same releases page, the voxtunnel_*.deb file
sudo apt install ./voxtunnel_*.deb
voxtunnel
from source (no root)
git clone https://github.com/remmmi/voxtunnel.git
cd voxtunnel/client
./install.sh          # menu launcher; --autostart for session start
python3 voxtunnel-tray.py
# server side from the same clone, as root on the VPS:
#   sudo ../server/setup-vps.sh --persist
Windows — WSL2, recommended
# the Linux client runs as-is inside WSL2: WSLg forwards the Windows
# microphone and shows the window on the Windows desktop
wsl --install -d Debian
# then, inside WSL, with the same voxtunnel_*.deb as above:
sudo apt install ./voxtunnel_*.deb
voxtunnel
# SSH keys go in the WSL home (~/.ssh), not the Windows one
# no WSL? native path (experimental, no build yet): client-windows/
macOS — from source, experimental
# no packaged build yet: the menu bar app runs from a clone
brew install ffmpeg python
pip3 install PyQt5
git clone https://github.com/remmmi/voxtunnel.git
python3 voxtunnel/client/voxtunnel-tray.py
# macOS asks for mic permission on first capture - details in client-macos/

Got a Mac or a Windows box? These clients have only ever seen CI runners. If you can spare ten minutes to try one on real hardware, open an issue with what worked and what broke — even "it launched" is gold.
